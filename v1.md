# 366 days — версии 1.x

Здесь собрано всё, что относится только к версиям **1.x**. Актуальная версия — **2.0**, её описание в [README](https://github.com/Mrvibecodic/366-days#readme).

## На чём собраны версии 1.x

Страница — надстройка над официальной страницей подписки Remnawave. От того, какая официальная версия внутри образа, зависит, с какой панелью всё работает.

| Версия | Официальная страница внутри | Панель |
|---|---|---|
| 1.2.0 – 1.2.2 | 8.0 | 3.0 |
| до 1.2.0 | 7.x | 2.x |

- Панель **3.x** — переходите на 2.0.
- Панель **2.x** — на 1.2.0 и новее не переходите. Оставьте ту сборку, которая у вас уже работает, и обновляйтесь после перехода на панель 3.x.

## Как остаться на 1.x

В `docker-compose.yml` укажите конкретный номер версии:

```
image: ghcr.io/mrvibecodic/366-days:1.2.2
```

Пока номер не поменяете, обновление само не приедет. До 1.2.0 в `docker-compose.yml` стоял тег `latest` — если он у вас так и остался, следующий `docker compose pull` принесёт 2.0.

## Настройка, которая была только в 1.x

`SUBPAGE_TG_SELFHOST` — откуда брать скрипт Telegram. По умолчанию `off`: скрипт грузился с `telegram.org`. Если люди открывали страницу без VPN и `telegram.org` у них был заблокирован, страница долго не открывалась — тогда нужно было поставить `on`, чтобы скрипт раздавался с вашего домена.

В 2.0 этой настройки нет: скрипт всегда лежит в образе и подгружается только внутри Telegram.

## Особенности 1.x

- **Долгий старт.** При каждом запуске контейнера страница пересобиралась 10–15 секунд, и только потом становилась доступна. В 2.0 это занимает около секунды.
- **Приложения «пилюлями».** Приложения одной платформы показывались рядом кнопок с переносом строк. В 2.0 вместо этого список или плитки.
- **Образ только под x86-64.** Образ для ARM появился в 2.0.

## Переход с 1.x на 2.0

1. Убедитесь, что панель версии 3.x.
2. В `docker-compose.yml` поменяйте номер на `2.0.0`.
3. Из `.env` можно удалить строку `SUBPAGE_TG_SELFHOST` — она больше не читается.
4. Если хотите плитки вместо списка, добавьте в `.env` строку `SUBPAGE_APPS_VIEW=tiles`.
5. Выполните:

   ```bash
   docker compose pull && docker compose up -d
   ```

Всё, что настроено в панели через Subpage Builder, переносить не нужно — оно подхватится как раньше.
